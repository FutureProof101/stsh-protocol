## The rule (CTO ruling 2026-07-27)

`ic-stable-structures` MemoryId allocation is **append-only, per canister**.

- New structures take **fresh** IDs.
- A retired ID is **never recycled**. Recycling one does not fail loudly:
  `ic-stable-structures` simply hands the new structure the old region's bytes,
  silently reinterpreting a decommissioned checkpoint as live state of a
  different type. There is no runtime error to catch — the corruption is silent
  and durable. That is why the lint refuses to build rather than warn.
- The same numeric ID across **different** canisters is legal and expected —
  stable memories are independent per canister.

**Discipline:** any commit that allocates or retires a MemoryId updates this
file **in the same change**. If this file and the code disagree, the lint fails;
the fix is to reconcile, then work out how the drift happened.

## Default-value discipline for eager cells (CTO ruling 2026-09-05)

**General rule for future pool eager cells** (`CTO_RULING_R2_REGION24_ABSENT_VS_INVALID_2026-09-05.md` §3). A new eager cell whose value has a **safe, in-bounds default** — a tunable parameter, as MemoryId 24 is — uses that default as its `Cell::init` value and traps only on present-but-invalid bytes. A cell whose value has **no safe default** — an accounting word, or a cursor whose "complete" state must never be assumed (MemoryIds 20, 21, 22) — keeps the sentinel default and the fail-closed trap; such a cell crosses the pre-F2-REDACT fixture only by re-pinning that fixture or by a documented reinstall boundary, decided per lane. The pre-F2-REDACT fixture is not sacrosanct, but it is the only cross-Wasm proof of the `depositor` widening and is not to be re-pinned casually.
